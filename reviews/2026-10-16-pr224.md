### R1 — P2 CODE_ERROR: validate policy identity and supported schema before early returns

[income_tax.py:309](https://github.com/hemmingsenpeter-byte/poltika/blob/2248390fa4b68042891c8be2e4cb26f3d83f73dc/src/poltika/engines/simulator/income_tax.py#L309)

`run_income_tax_module()` parses a spec and can return a scenario or draft-gate result before validating its policy identity or supported schema. With the ordinary scenario's income set to `None`, supplying `policy_specs/working_for_families` returns `IT_FACTS_UNVERIFIED` with `trace.policy_id=working_for_families` and `component_id=basic_annual_income_tax`. AS reproduces the same cross-policy problem. A temporary copy of the real draft declaring schema `999` returns `IT_POLICY_NOT_APPROVED` normally, while `load_policy_parameters()` correctly raises `UnsupportedSchemaVersionError` for those same bytes.

Expected: reject a wrong module policy or unsupported schema before producing a normal module result, including refusal paths. This is the architecture's existing schema/identity contract, not a new statutory rule. Add direct negative tests for the module entry point; the existing wrong-preloaded-policy test does not cover it.

Verify that a real draft result exports faithfully and that changed bound artifacts are detected. The missing-artifact and double-read reproductions belong to this one trace-binding finding.
