## Discrepancies and resolution

All classifications below are proposed `CODE_ERROR`; none required a policy
interpretation decision or a protected expected-value change.

1. **Stored export evidence could drift** (`api/workbench.py`, original
   `_payload`, lines 187–208). Running an option, then changing a bound policy
   file, still exported regenerated examples and live sources beneath the old
   run ID. Exports now check every recorded artifact hash before regeneration
   and return a path-free 409 requiring a rerun if evidence changed.
2. **A shared status quo accepted different populations**
   (`api/workbench_tables.py`, original `_fiscal_tab`, lines 177–181). Changing
   only a population's ID preserves every baseline total, so two different
   runs were exported against one displayed population and provenance record.
   Comparisons now require matching population content hash, code identity
   and policy artifacts; an incompatible comparison returns 409.
3. **Configuration errors exposed server paths** (`api/workbench.py`,
   original `check`, line 171). A copied WFF spec naming a missing source
   catalog returned 200 and included the resolved absolute path in its
   per-override problem. Only caller-correctable reform exceptions are caught
   now; deployed configuration failures reach the existing generic 500
   handler. Unsupported/invalid overrides retain their useful messages.
4. **An entirely unresolved headline became zero**
   (`api/workbench_tables.py`, original `_summary`, line 116). Four toy
   households with missing family scheme income returned a family-tax-credit
   headline with `change_total: "0.00"`, `mean_change: null`, and weighted
   `not_calculated: "1000"`. The headline now says `not calculated`, including
   XLSX and CSV; calculated identity changes remain numeric zero.
5. **Invalid records disappeared from coverage**
   (`api/workbench_tables.py`, original `_measure_changes`, lines 120–130,
   and `_fiscal_tab`, lines 201–207). Records excluded before simulation were
   absent from all workbench coverage counts and the calculated-share
   denominator. Invalid weight now appears separately in fiscal and grouped
   coverage and is included in headline `not_calculated` and the denominator.
