## Findings

1. **P2 — CODE_ERROR**, `api/hardening.py:87`: `Content-Length` containing 5,000
   digits passes `isdigit()` and makes `int()` raise Python's digit-limit `ValueError`.
   A POST to `/household/calculate` reproduced HTTP 500; the expected rejection is 413.
   Proposed fix: bound the normalized digit count before integer conversion, including
   harmless leading zeroes, and add negative and boundary regression probes.
2. **P2 — CODE_ERROR**, `api/main.py:110`: an unexpected route exception produces
   Starlette's outer `ServerErrorMiddleware` response after the security middleware
   has unwound. A temporary route raising `RuntimeError` returned 500 with only
   Content-Length and Content-Type; the advertised security headers were absent.
   Proposed fix: add a safe generic error handler with the same headers and regression
   coverage. The existing `PoltikaError` 500 handler already keeps the headers.

3. **P2 — CODE_ERROR**, `api/microsim.py:161`: cache eviction/publication falls
   outside the new computation lock. With a full cache (limit reduced to one for the
   probe), pause the first run immediately before insertion after its eviction and
   accept a second run. Resume the first: the cache holds two entries despite its
   one-entry limit. Proposed fix: publish/evict while still holding admission, with
   a concurrent HTTP regression. Fetch should take one atomic snapshot instead of
   a separate membership test and lookup that can race eviction.
4. **P2 — CODE_ERROR**, `api/household.py:405`: the newly merged #131 validates
   answer labels, but declined labels remain unvalidated. POST intake with an
   unknown, unindexed child, or out-of-range child label returned 200 and asked
   `children[0].best_start_cohort` again. This contradicts the intake contract that
   declining a fact stops its question. Proposed fix: use the same catalogue/index
   validation, return 422 naming `declined[index]`, and normalize valid indexed
   labels before exclusion. This is an adjacent input-validation gap exposed by
   the #131 follow-up review, not statutory logic.
5. **P2 — CODE_ERROR**, `.github/workflows/tests.yml:74`: root inspected failed
   main CI run `36651304118`, which exited 141 during
   `docker logs ... | grep -q ...` under `pipefail`. A long startup log makes grep
   close its input and docker fail with SIGPIPE. Proposed fix: save docker's output
   to a file, then grep it, matching the existing curl smoke-check pattern.

The author packet was read after the expected contract and the first two
reproductions were established. It confirms the every-response and malformed-length
requirements. Findings 3–5 were recorded before their corresponding fixes.
