## Expected behaviour

The only taxable amount is their supplied, single, exact-year
`UNSPLIT_TOTAL/IT_ANNUAL_TAXABLE` spell. Its Decimal is preserved without
arithmetic. Unknown stays unknown; neither another person nor a different
income basis supplies the amount. No conversion, annualisation or
interaction rule is inferred. Known exclusions outrank unresolved facts.
The runner preserves the engine's period, version, policy and trace gates.
The reverse adapter preserves identity, asserted meaning and period.
Existing households retain their hashes. Tests must detect violations of
these contracts, and a material model relationship needs its change record.

### R4 — P2 / CODE_ERROR: adapter stamps an excluded year onto 2026–27

At [household_mappings.py:846](https://github.com/hemmingsenpeter-byte/poltika/blob/f31a8d3e44b97ba1785610cdd37489da78d3ca53/src/poltika/scenarios/household_mappings.py#L846), the guard rejects
`STANDARD_2026_27` with a different supplied period, but permits the
converse. Both `OTHER_STANDARD_YEAR` and `NON_STANDARD_YEAR` with a known
amount can be adapted using `INCOME_TAX_YEAR_2026_27`. The resulting
household contains a taxable-income spell dated 2026–27 despite its
explicit contrary year assertion. Scenario round-trip equality still
passes; it cannot prove that the new dates preserve the asserted meaning.

Reproduced on the reviewed head for each excluded basis:

```text
other_standard_year 2026-04-01 2027-04-01 60000
non_standard_year   2026-04-01 2027-04-01 60000
```

The engine remains `unsupported` / `IT_TAX_YEAR_NOT_MODELLED`; no wrong
calculated amount is demonstrated. This is a narrower adapter/data-contract
defect. Reject a contradictory supplied period with `AdapterRefused`, and
test both directions without manufacturing a year for unknown inputs.

### R7 — P2 / CODE_ERROR: Q10 can suppress a known numeric exclusion

At [household_mappings.py:732](https://github.com/hemmingsenpeter-byte/poltika/blob/f31a8d3e44b97ba1785610cdd37489da78d3ca53/src/poltika/scenarios/household_mappings.py#L732), Q10 inspects every income type using the
taxable basis, whereas amount selection at lines 737–739 reads only
`UNSPLIT_TOTAL`. A straddling spell of an ignored type therefore causes a
refusal before the mapper reads an otherwise valid exact-year taxable
amount. The fallback at line 787 replaces that known amount with `None`.

Minimal reproduction, run from the reviewed checkout:

```python
from datetime import date
from tests.unit.scenarios.test_household_income_tax import (
    _couple, _spell, _whole_year, YEAR,
)
from poltika.scenarios.household_mappings import run_household_income_tax
from poltika.semantics.household import IncomeType

for amount in ("-1", "15600.25"):
    for extra in (False, True):
        spells = [_whole_year("a", amount)]
        if extra:
            spells.append(_spell(
                "a", date(2026, 3, 1), YEAR.end, "1",
                income_type=IncomeType.EMPLOYMENT_EARNINGS,
            ))
        result = run_household_income_tax(_couple(*spells), "a", tax_year=YEAR)
        print(amount, extra, result.outcome, result.code)
```

Actual output:

```text
-1 False unsupported IT_NEGATIVE_INCOME_NOT_MODELLED
-1 True needs_review HOUSEHOLD_SPELL_PERIOD_MISMATCH
15600.25 False unsupported IT_FRACTIONAL_INCOME_NOT_MODELLED
15600.25 True needs_review HOUSEHOLD_SPELL_PERIOD_MISMATCH
```

These households pass schema validation. The ignored typed spell neither
replaces nor requires apportionment of the independently supplied annual
amount. The specification's outcome contract and the mapper's own
precedence promise require the known exclusion to survive. This extends
the author's A4 beyond a wrong-type spell alone: that earlier conservative
case did not demonstrate loss of a separately known exclusion. Align Q10
with the same selected person/type/basis spell set used for extraction,
and test both negative and fractional cases with the extra spell.

### R3 — P2 / TEST_ERROR: core mapping regressions survive the tests

The [new mapping tests](https://github.com/hemmingsenpeter-byte/poltika/blob/f31a8d3e44b97ba1785610cdd37489da78d3ca53/tests/unit/scenarios/test_household_income_tax.py#L84) use default runner settings and adapter identity,
and do not combine a selected person's exact-year amount with another
person's straddling spell. Isolated mutations can broaden the refusal's
income bases or person scope, ignore caller policy settings, or drop the
adapter's selected identity without failing the mapping suite.

Add direct, non-default cases for `policy_dir`, `modelled_date` and
`requested_policy_version`; use a custom adapter `person_id` and period;
and test irrelevant bases and other people's straddling spells. These are
meaningful semantic boundaries, especially where the current draft gate
makes otherwise different results look alike. Keep tests that exercise
both adapter directions independently of the round-trip identity.

Thirteen independently verified behaviour-changing mutations each left all
62 mapping tests green:

| Mutation | Behaviour a direct regression test should pin |
| --- | --- |
| Widen `_IT_BASES` to every basis | A gross-income straddler cannot refuse a valid taxable amount |
| Pass every person's ID to Q10 | A partner's straddler cannot refuse the selected person's valid amount |
| Drop `policy_dir=policy_dir` in the engine call | The trace binds the supplied policy, including a synthetic probe version |
| Drop `modelled_date=modelled_date` | `2027-04-01` is refused and traced as that date, rather than run at the default date |
| Drop `requested_policy_version=requested_policy_version` | A mismatched requested version raises `PolicyVersionMismatchError` |
| Replace adapter `person_id` with `"taxpayer"` | Custom identity is retained on both person and spell |
| Ignore adapter `tax_year` for `OTHER_STANDARD_YEAR` | An explicitly supplied 2025–26 period stays on the spell |
| Q10 checks only the lower year boundary | A spell ending `2027-05-01` is a period mismatch, not unknown income |
| Refusal fallback reads the claimant's facts | A selected partner's refusal cannot inherit the claimant's non-residence exclusion |
| Include entirely disjoint previous-year taxable spells | A separate year's entry cannot refuse the current year's exact amount |
| Swap deductions/losses in both mapping directions | A directly constructed household with different statuses maps each field correctly |
| Ignore income type in amount selection | A typed spell cannot substitute for the declared unsplit annual total |
| Replace adapter `household_id` with a constant | Custom household identity is retained |

The last case matters separately from the successful-mapping isolation
test: it exercises the fallback after mapping refuses. Mutation probes
used disposable source copies and the locked environment; the author
worktree stayed unchanged. Existing tests do kill removal of Q10, so the
finding concerns specific unprotected branches, not a claim that the
entire suite is vacuous. Overall, 34 bounded mutations gave 21 killed,
13 surviving and no harness/collection errors. The symmetric
deductions/losses swap demonstrates why inverse round trips need separate
assertions of each direction's field semantics.
