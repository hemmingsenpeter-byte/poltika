## Independently derived expected behavior

1. Three templates end in a confirmation of the exact submitted inputs,
   policy/source/locator, requested versions/periods, population and limits.
   Late checks and requests cannot approve different edits or navigate after
   the user leaves. Unsupported or unresolved values remain explicit.
2. The seven-tab workspace preserves stored identity, original context and
   recorded inputs; static routes keep real IDs after hydration. API clients
   still receive JSON and the development server supports the documented
   household API flow.
3. Edit-as-new copies the complete supported draft, including both comparison
   options and household facts/dates/versions. It never mutates a stored run
   or silently drops unsupported structure. Re-run uses the existing engine
   route; CSV/XLSX exports read the selected retained result.
4. Known block bodies are validated before rendering; future block types have
   an explicit unsupported marker. Household/parameter strings keep their
   exact precision; population aggregates display three significant figures
   without rounding stored or exported values.
